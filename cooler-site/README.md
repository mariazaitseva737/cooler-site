# Прохлада / Cooler — сайт

Лендинг на русском и английском, журнал со статьями, форма для email и аналитика. Собран на [Astro](https://astro.build), хостится на Netlify.

```
/                 лендинг (RU)
/en/              лендинг (EN)
/blog/            журнал (RU)
/blog/<адрес>/    статья (RU)
/en/blog/...      то же на английском
/thanks/          страница «Спасибо» после формы
```

## 1. Выложить на Netlify

1. Создайте пустой репозиторий на GitHub (например, `cooler-site`) и загрузите туда содержимое этой папки. Проще всего через GitHub Desktop: File → Add local repository → Publish. Папки `node_modules` и `dist` загружать не нужно, они уже в `.gitignore`.
2. В Netlify: **Add new project → Import an existing project → GitHub** → выберите репозиторий. Настройки сборки подтянутся из `netlify.toml`, менять ничего не нужно.
3. Нажмите **Deploy**. Через минуту-две сайт будет доступен по адресу вида `something.netlify.app`.
4. **Project configuration → Environment variables** — добавьте переменные (образец в `.env.example`):
   - `SITE_URL` — адрес сайта, например `https://cooler-app.netlify.app` или ваш домен. От него зависят canonical-ссылки и карта сайта для Google.
   - `PUBLIC_APP_URL` — ссылка на веб-приложение. Пока приложения нет, оставьте пустой: кнопки «Попробовать бесплатно» будут вести к форме email.
   - `PUBLIC_POSTHOG_KEY` и `PUBLIC_POSTHOG_HOST` — аналитика, см. ниже. Без ключа аналитика выключена.
5. После изменения переменных: **Deploys → Trigger deploy**.

### Про бесплатный лимит

На бесплатном плане 300 кредитов в месяц. Каждая публикация стоит 15 кредитов, гигабайт трафика — 20. Когда кредиты кончаются, сайт выключается до следующего месяца. Поэтому правки в статьях лучше копить и публиковать пачкой, а не по одной опечатке.

## 2. Email: Netlify Forms

Отдельная база не нужна. Формы на сайте уже размечены для Netlify (`data-netlify="true"`), поэтому:

1. После первого деплоя откройте **Forms** в Netlify и включите обработку форм (Enable form detection), если она выключена. Затем сделайте ещё один деплой.
2. Заявки появятся в разделе **Forms → waitlist**. У каждой есть поля `email`, `lang` (язык) и `source` (откуда отправили: `hero`, `bottom`, `blog`).
3. Уведомления на почту: **Forms → Form notifications → Add notification → Email notification**.
4. Выгрузка списка: кнопка **Download as CSV** в разделе формы.

Защита от спама — скрытое поле-ловушка, отдельная капча не нужна.

## 3. Аналитика: PostHog (необязательно)

Считает воронку без cookies и без записи экрана.

1. Зарегистрируйтесь на [posthog.com](https://posthog.com), при регистрации выберите облако **EU**.
2. В настройках проекта включите **Discard client IP data**.
3. Скопируйте Project API key в `PUBLIC_POSTHOG_KEY`, а в `PUBLIC_POSTHOG_HOST` укажите `https://eu.i.posthog.com`.

Какие события уже размечены:

| Событие | Что значит |
|---|---|
| `$pageview` на `/` или `/en/` | открыли лендинг |
| `try_click` | нажали «Попробовать бесплатно» (поле `place` — где именно) |
| `$pageview` на `/thanks/` | оставили email, это главная конверсия |
| `email_submit` | нажали «Отправить» в форме (может не дойти, если страница успела смениться, поэтому считайте по `/thanks/`) |

События приложения (прошла онбординг, первая отметка, вернулась через день и через неделю) появятся, когда будет готово само приложение.

## 4. Статьи

Каждая статья — отдельный файл:

```
src/content/articles/ru/<адрес>.md
src/content/articles/en/<адрес>.md
```

Сверху в файле идут поля (заголовок, SEO, «Коротко», термины, вопросы, источники), ниже — текст статьи. Разделы текста начинаются с `## Заголовок`, списки — с `- `.

### Редактировать через Pages CMS (рекомендую)

1. Откройте [app.pagescms.org](https://app.pagescms.org) и войдите через GitHub.
2. Выберите репозиторий сайта. Конфигурация уже лежит в файле `.pages.yml`.
3. Слева появятся «Статьи (RU)» и «Articles (EN)». Там можно править поля и текст в обычном редакторе.
4. Нажали **Save** — Pages CMS сохраняет изменения в GitHub, Netlify сам пересобирает сайт.

Чтобы спрятать статью, не удаляя, поставьте галочку **Черновик**.

### Как связать русскую и английскую версию

У обеих версий должно быть одинаковое поле **Ключ перевода** (`translationKey`). По нему сайт ставит переключатель RU/EN и сообщает Google, что это перевод одной статьи.

## 5. SEO: что уже сделано и что заполнять

Для каждой страницы сайт сам собирает:

- `<title>` и meta description из полей **SEO-заголовок** и **SEO-описание**;
- canonical-ссылку и `hreflang` для русской и английской версии;
- Open Graph для превью в мессенджерах и соцсетях;
- структурированные данные: `MedicalWebPage`, хлебные крошки, `FAQPage` из блока «Вопросы и ответы»;
- карту сайта `/sitemap-index.xml` и `robots.txt`.

Когда пишете новую статью:

1. **SEO-заголовок** — до 60 знаков, с главным запросом в начале. Пример: «ЗГТ при менопаузе: польза, риски и вопросы врачу».
2. **SEO-описание** — 120–160 знаков: о чём статья и что человек из неё узнает.
3. **Главный поисковый запрос** — фраза, которую вбивают в поиск. На сайте она не выводится, это подсказка автору: она должна быть в заголовке, в первом абзаце и в одном из подзаголовков.
4. **Адрес** — латиницей через дефис, коротко: `zgt-pri-menopauze`, а не `statya-1`.
5. **Вопросы и ответы** — 2–3 вопроса так, как их задают в поиске. Ответ должен быть и в тексте статьи.
6. **Источники** — ссылки на рекомендации и исследования. Для медицинских тем это важно и для доверия читателей, и для поиска.
7. **Научный редактор** — пока там стоит заглушка `[ИМЯ ВРАЧА, …]`, на сайте строка не показывается. Впишите настоящее имя, и она появится вместе с разметкой `reviewedBy`.

После запуска добавьте сайт в [Google Search Console](https://search.google.com/search-console) и [Яндекс Вебмастер](https://webmaster.yandex.ru) и отправьте туда адрес карты сайта: `https://<ваш-домен>/sitemap-index.xml`.

## 6. Что поменять перед запуском

- `src/i18n/ui.ts` → `CONTACT_EMAIL` — ваш адрес для «Написать нам».
- Название продукта меняется там же: `APP_NAME` и `APP_NAME_IN` (форма «в Прохладе»).
- `SITE_URL` в Netlify, когда подключите домен.
- Страница политики конфиденциальности. Вы собираете email, и в США, и в ЕС для этого нужна страница с политикой. Её лучше написать с юристом или по проверенному шаблону.
- Имя врача-редактора в статьях.

## Запустить у себя (необязательно)

Нужен Node.js 22 или новее.

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # готовый сайт в папке dist/
```
